# Goal paths: rules

The user wants Recurse to ask "What do you want to achieve?" and offer career and study goals (software engineer, embedded software engineer, Python developer, web developer, security engineer, network engineer, data analyst, DevOps and cloud engineer, SWE internship, CCNA, computer science degree). Each goal is a learning path (a "collection"). Recurse alone must contain everything needed to reach the goal: if a learner did only this path (lessons, questions, activities, labs, challenges and projects), they could get hired for that role or pass that course load. Outside resources are optional extras, shown in a "Recommended" tab with a reason for each.

Method:
1. Write down what the goal really requires: what entry-level job postings for that role commonly ask for, what interviews test, and what widely used public roadmaps cover (use your knowledge; do not copy text from any site). Put this requirement list in your scratch folder.
2. Map each requirement to existing packs (the full list of pack ids and names is in /tmp/claude-0/-home-user/7b6c6500-00da-5530-a470-6a297b2f0037/scratchpad/briefs/pack-list.txt; other agents are adding ccna-troubleshooting, ccna-exam-strategy, react-basics, swe-cloud-devops, swe-advanced-structures, swe-oop-design, c-memory, java-basics and security-network-defense right now, so you may reference those ids too). Reuse existing packs; never duplicate one.
3. Write the missing packs (you own them). Same quality bar as the strongest existing packs: 8 to 10 sections, about 2,600 to 3,200 words, 34 to 40 questions of 7+ types, a check and a pitfall per section, 12+ key terms (they feed the glossary), 3 to 6 verified resources, activities where a widget genuinely fits (see src/activities/catalog.js; the Python and JavaScript code-runner works for small programs; the Python runner has no third-party packages, no sqlite3 and no input()).
4. Write the path file src/data/collections/<path-id>.json (you own it). Shape: copy src/data/collections/swe-internship.json and ccna.json: id, name, short (2 to 4 capital letters, unique), kind ("career" | "certification" | "school" | "foundation"), icon (one of: network, code, cpu, globe, shield, sigma, braces, briefcase, chart, circuit, cloud, graduation, router), hue (0 to 360, pick one not too close to existing paths: 200 CCNA, 268 SWE, 222 CS, 192 web, 354 security, 292 math), tagline (one line), description (3 to 4 sentences), outcome (what the learner can do at the end, concretely), hours (honest estimate), stages (5 to 8, each with id, title, summary, milestone, topics in learning order, and labs, challengeSets, projects where relevant; stage "weight" only if a certification blueprint weights it), projects (ids), and resources (5 to 9 entries: { "title", "url", "kind", "note" } where note says WHY it is worth adding alongside Recurse in one sentence; free first; verify each URL returns 200 with curl as in the common rules).
5. Projects: if the role needs portfolio evidence that existing projects do not give, add 1 or 2 projects in src/data/projects/<id>.json following docs/projects.md (you own new project files). Existing project ids are listed in /tmp/claude-0/-home-user/7b6c6500-00da-5530-a470-6a297b2f0037/scratchpad/briefs/project-list.txt.
6. Validate: node scripts/validate-packs.mjs and node scripts/validate-content.mjs must show no errors from your files (validate-content checks path topic ids, labs, challenge sets and projects).
7. Report the requirement list mapped to topics (compact), the packs and projects you wrote, and the path file.
